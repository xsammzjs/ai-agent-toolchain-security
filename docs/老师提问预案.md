## 三、老师最可能问的 8 个问题（照着准备）

### Q1「这个跟市面上的工具有什么区别？」

```
传统依赖扫描（Snyk / Dependabot / pip-audit / Trivy）
  → 只查依赖包的已知 CVE，根本不解析 SKILL.md

同赛道（SkillLens / ClawGuard / MCP-Sentinel / TraceShield）
  → 全是单点检测：「这个 Skill 有 13 个风险点」，然后就结束了

我们：
  → 检测 AI 技能包（传统工具完全没覆盖这一层）
  → 跨资产关联：把分散的单点还原成完整攻击链
  → 依赖侧也有独立能力：置信度评级 + EPSS 优先级
  → 全离线、零调用成本、每条结论能翻代码核验
```

**一句话版**：「Snyk 查依赖包，我们查技能包，还做跨资产关联。」

### Q2「为什么用华为云？」

> 「赛题硬性要求作品在华为云上部署，评委复现时会看是不是真跑在华为云上。
> 另外 RDS/Redis 是赛题点名要关联的资源。
> 我们存储层做了抽象（`modules/store.py` 的 `StorageBackend` 接口），
> **接云资源业务逻辑一行不用改，只换数据源和部署位置**。」

### Q4「AI 会不会乱说？」

> 「不会，而且这是**代码层面强制**的。`adjudicator.py` 里 AI 只被允许输出两个字段：
> `verdict`（行为意图：恶意/可疑/正常）与 `scope`（外发范围：固定结构/通用内容/不外发），
> 而且**必须附带原文行号**——服务端会校验行号范围，指到 `try:`/`pass` 这类无信息量行时
> 会就地吸附到有内容的行，人工当场就能翻原文核对。
> 没配大模型时降级为本地模板并明示『未调用大模型』——
> **宁可降级，也不伪装**。」

## 四、容易被问住的两个细节（提前知道答案）

### ① 「98.1% 和 98.0% 有什么区别？」

别慌，**两个都对，是不同指标**：

| 指标 | 算法 | 含义 |
|---|---|---|
| **98.1%** | 105/107 | **整体准确率**（所有样本判对的比例） |
| **98.0%** | 100/102 | **特异度**（良性样本里正确放行的比例） |

98.1% 比 98.0% 高，是因为 5 个恶意样本全判对了（100% 检出），
把整体准确率往上拉了。

### ② 「误报率 58.6% 怎么变成 2.0% 的？」

这是**优化前后的对比**，不是两个版本打架：

```
初始：100 个真实科研技能，58.6% 被误判为高危
  → 根因：规则分不清「文档在描述怎么做」和「技能在执行什么」

三轮 CodeArts 审计后：2.0%
  → 改的是判定逻辑（跨行组合规则），不是简单调阈值
  → 同期恶意样本检出率保持 100% 无回退
```

**证据在** `docs/CodeArts审计实践.md`（有完整的 11 条建议和逐条处理）。
