## 先看这一段（如果你只有 3 分钟）

1. **AI 助手可以像装插件一样装「技能包」**，这些技能包能读写你的文件、跑命令、联网上传东西。

## 一、这到底是个什么东西

### 1. 背景：AI 也会「装插件」

现在越来越多公司让 AI 助手（Agent）去干实事——查资料、写代码、跑流程。为了让它更擅长，这些助手会安装一个个**「技能包」（Skill）**。

一个技能包长这样：

```
my-skill/
├── SKILL.md        ← 一份说明书，告诉 AI "我能干什么、怎么用"
├── scripts/        ← 可选的脚本
└── requirements.txt ← 可选的依赖清单
```

`SKILL.md` 就是一份普通的 Markdown 文件，用自然语言写。**正因为是自然语言，它既能让 AI 做事，也能骗 AI 干坏事。**

### 2. 问题出在哪

一个技能包想做坏事，能干的事其实就那么几类，我们把它们叫**「能力原子」**：

| 能力原子 | 大白话 |
|---|---|
| 读凭据 | 读你的环境变量、SSH 私钥、配置文件里的密码 |
| 外发 | 把东西传到某个网址（可能是任意网址） |
| 执行 | 跑 shell 命令 |
| 隐匿 | 想办法不被发现 |
| 持久化 | 偷偷留下后门 |
| 控制 | 接管 AI 的行为 |

**关键在于：单个技能包看起来都很正常。**

- 一个「环境诊断工具」会读环境变量 → 正常，诊断环境就需要
- 一个「遥测上报工具」会往某个域名发数据 → 正常，上报统计就需要

**但把它们装到一起，就出事了：**

> 技能 A 读出密钥 → 技能 B 把它发到任意网址
>
> 两个技能各自都没问题，**合起来是一条完整的窃密链**。

这就是这个项目要解决的问题：**危险存在于组合里，而现在的工具都只看单个。**

### 3. 所以我们做了什么

把一组技能包一起丢进去，它跑完给你一张**决定书**：

```
❌ 不可直接安装 · 建议人工复核
组合风险 1 条（严重 1） · AI 判断 2/2 · 技能未声明依赖
证据位置：env-diagnostic-collector:行 7 → 组合风险 CRED_EXFIL
```

注意最后那行 —— **它告诉你是哪个文件的第几行触发了哪条规则**。你打开原文一查就知道对不对，**不用相信这个工具**。

## 二、它是怎么工作的（四步）

```
第 1 步  导入      上传技能包，或点「用内置示例」
第 2 步  规则快筛  32 条规则，纯本地运行，秒出
                   → 把每个技能翻译成「它有什么危险能力」
第 3 步  AI 意图   用大模型判断「它到底想干什么、往外发什么」
                   → 每条判断必须引用原文行号
                   → 大模型挂了就直接拒判，绝不输出「可安装」
第 4 步  组合判定  三个条件同时成立才算一条风险链：
                   ① 能力互补（一个会读、一个会发）
                   ② 意图不良（大模型判定它目的不纯）
                   ③ 外发通道是「啥都能带」型
                   → 出决定书 + 关系图 + 合规对照
```

**为什么要分「规则」和「AI」两段？**

| | 规则（第 2 步） | AI（第 3 步） |
|---|---|---|
| 优点 | 快、确定、离线可用 | 能理解「自然语言伪装成正常功能」 |
| 缺点 | 只认字面模式 | 可能出错、可能挂掉 |

**分工很清楚：规则给确定性，AI 只给意图判断，两者不互相覆盖。**

**为什么大模型挂了要「拒判」而不是「放行」？**

因为这是安全工具。**判断不出来 ≠ 安全。** 宁可显示「无法判定，请人工复核」，也不能显示「可以安装」然后出事。这在安全领域叫 **fail-closed（失败即拒绝）**。

## 三、三个真正不一样的地方

市面上已经有 8 个商业扫描器（NVIDIA、Cisco、腾讯、Snyk 等）和 5 个学术界工作，但**它们都在做同一件事：单点检测** —— 回答「这个技能危不危险」。

我们做的是另一件事：

| | 别人 | 我们 |
|---|---|---|
| 问的问题 | 这个技能危不危险？ | **这组技能凑一起会怎样？** |
| 输出 | 一个风险分数，比如 0.87 | **一份能签字的安装决定** |
| 依据 | 黑箱分数，你看不懂 | **原文行号 + 规则编号，你自己查** |
| AI 挂了 | 降级给个大概分数 | **直接拒判，不给结论** |

**同行里没有人回答「模型挂了怎么办」和「这个结论能不能让人签字」这两个问题** —— 前者是安全底线，后者是它能不能真的用起来的关键。

## 七、名词表

| 词 | 意思 |
|---|---|
| **Agent / AI 助手** | 会调用大模型、能自己动手干活的 AI 程序 |
| **技能包 / Skill** | 给 Agent 装的插件，一个文件夹 + 一份 `SKILL.md` 说明书 |
| **SKILL.md** | 技能包的说明书，纯自然语言 —— **这既是它能被理解的原因，也是能被攻击的原因** |
| **能力原子** | 把技能的危险能力归成 6 类：读凭据 / 外发 / 执行 / 隐匿 / 持久化 / 控制 |
| **MaaS** | 大模型即服务（Model as a Service），这里指华为云的大模型接口 |
| **fail-closed** | 失败即拒绝。判断不出来时不给「通过」结论，而是拒判 |
| **OWASP Agentic Skills Top 10** | OWASP（一个国际安全组织）发布的「AI 技能包十大风险」标准 |
| **SCR-Bench / CompoSkill** | 学术界公开的基准数据集，别人可复现，我们的数据就是跟它们对齐测的 |
| **依赖漏洞** | 你的代码引用的第三方库有已知安全漏洞（跟技能本身的风险是两回事） |
| **行号证据** | 结论直接指向原文件的第几行，你自己打开就能核对 |

## 九、常见问题

**Q：为什么叫「体检站」？**
体检的意思是给一个**判断 + 依据**，而不是给一堆告警让你自己看。

**Q：这个能防住所有攻击吗？**
不能。它防的是**「组合起来才出事」**这一类。单个技能自己就明显有问题的，它也会报。但它不替代人工审核，结论里也会写「建议人工复核」。

**Q：为什么代码量比一般课程设计多？**
因为大部分代码在**可复现的评测和自动校验**上 —— 107 个语料、公开基准对标、9 条守卫脚本。这些是让结论可信的部分，不是堆功能。

**Q：赛题要求用华为云，现在用上了吗？**
AI 判断走的是华为云 MaaS；数据库那层（`modules/storage/huawei.py`）已经写好，**等代金券到位后切换配置即可上线**，这部分材料里已经写明。
