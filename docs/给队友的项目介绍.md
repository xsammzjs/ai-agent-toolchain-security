## 一、一句话

**把几个 AI 技能包一起丢进去，它告诉你这批东西该不该装，以及是谁在搞事。**

## 二、它解决什么问题（用你熟悉的话说）

你做日志审计助手的时候，遇到的是「一堆日志进来，怎么判断有没有问题」。
我这边遇到的是同一类问题的另一个场景：

> 企业给 AI Agent 装「技能包」（SKILL.md 格式的插件）时，只能靠人工看一眼。
> 但**这些技能包组合起来才危险** —— A 读密钥、B 往外发数据，单独看每个都是"正常功能"，装在一起就是一条窃密链路。

**关键词几乎一样：单点看不出来，组合起来才有事。**

| 你的反洗钱项目 | 我这个项目 |
|---|---|
| 分析对象：交易流水 | 分析对象：AI 技能包 |
| 单点看不到的：单笔交易正常，串起来是洗钱 | 单点看不到的：单个技能正常，凑一起是窃密 |
| 输出：交易合规判定 | 输出：**安装决定**（可装 / 不可装 / 需复核） |
| 合规依据：反洗钱法规 | 合规依据：OWASP Agentic Skills Top 10 |

## 四、核心机制：四步流水线

```
第1步  导入        上传技能包（.md 或 .zip），或点「用内置示例」
第2步  规则快筛    32 条正则规则，纯本地，秒出 → 把每个技能翻译成「有什么危险能力」
                   （8 个能力原子：读凭据 / 外发 / 执行 / 隐匿 / 持久化 / 控制）
第3步  AI 意图     调大模型判断「它想干什么 + 往外发什么」
                   ⚠️ 每条判断必须引用原文行号 —— 不用相信工具，自己查行号
                   ⚠️ 模型挂了 → 拒判（fail-closed），绝不输出"可安装"
第4步  组合判定    三要素成链：能力互补 × 意图不良 × 外发通道是"啥都能带"型
                   三个闸门全过才算一条风险链 → 出安装决定 + 关系图 + 合规对照
```

## 五、三个独有性（别人没有的）

**① 组合成链**
市面上 8 个商业扫描器（SkillShield / Vett / Aguara / JadeGate / Snyk / 腾讯 AI-Infra-Guard / Cisco skill-scanner / NVIDIA SkillSpector）**全是单点检测** —— 回答"这个技能危不危险"。
我回答的是"**这组凑一起会怎样**"。

**② 行号可核验**
不是"这个技能很可疑"，而是"**SKILL.md:42 触发 R07 读环境变量、SKILL.md:117 触发 R12 外发到任意域名**"。
国际同行输出的都是 `risk score: 0.87` 这种黑箱分数，**没人回答"模型挂了怎么办"和"这个结论能不能让人签字"**。

**③ fail-closed**
AI 挂了就拒判。工业场景 care 这个，论文不 care。

## 七、⚠️ 和你项目的关系（重点看这节）

### 相同的地方（可以在老师面前统一讲）

**方法论完全一致**：

```
把分析对象建成图  →  大模型判断意图  →  映射合规标准  →  出可执行结论
```

都是「从单点告警升级到关联判定」，都是「规则给确定性 + 大模型给可核验的判断」。

**这一句可以两个人一起说**：
> 「我们两个项目做的是同一套方法论，只是领域不同 —— 他做交易反洗钱，我做 AI 技能供应链安全。核心都是**关联判定**，不是单点检测。」

### 不同的地方（老师问"你俩什么关系"时用）

| | 你的反洗钱 | 我的技能体检 |
|---|---|---|
| 领域 | 金融 | AI 安全 |
| 图里是什么 | 账户、流水、实体 | 技能、能力、外发通道 |
| 合规依据 | 反洗钱法规、MAESTRO 类 | OWASP Agentic Skills Top 10 |
| 结论形态 | 交易是否可疑 | 这批技能能不能装 |

### 撞车风险（一条要守的纪律）

**⚠️ 咱们俩都用「图计算」这个词，老师可能会觉得撞车。**

- **你的项目叫「图计算与大模型」** —— 这是你的标题，**不用改**，那是国赛级的正统表述。
- **我这个项目不提「图计算」** —— 因为我的图**不是拿来算的**（没有 GNN、没有图算法、没有 PageRank），只是**算完之后画出来给人看证据**。我这边统一叫「**风险证据关系图**」「资产关系视图」。

**老师真问起来就这么答**：
> 「他那个是**用图算**（图计算是方法）；我这个是**算完画出来**（图是证据的呈现）。我这边真正的算法是规则 + 大模型 + 成链判定，图只是让人一眼看清'谁读密钥、谁往外发、怎么串起来的'。」

**这样做的好处**：两个人讲的是同一个圈子的两种做法，不撞车，反而显得这个思路被两个人分别验证过。

## 八、老师可能会问的（我这个项目的）

| 问题 | 答题要点 |
|---|---|
| **跟华为云什么关系？** | 存储层已实现（`modules/store.py` 抽象 + `modules/storage/huawei.py` 的 RDS/Redis 适配 + asset_node/asset_edge/scan_record 三张表），业务代码不用改，**待代金券到位后填 .env 连接串即可上线**；AI 分诊用的就是**华为云 MaaS** |
| **8 个商业扫描器、5 篇学术都做了，凭什么是你？** | 别人做单点检测，我做组合成链。KnotScryer 证明单点会**漏**（13.7% 危险链全由判 safe 的技能组成），我们证明单点会**响**（假链路 5/7 也报警）—— **两面合起来，单点评分不能作为放行依据** |
| **依赖漏洞市面一堆现成的（pip-audit / Snyk），为什么还做？** | ① 依赖不是主线，是关系图里一类节点（技能→依赖→CVE 成链）；② 我实现的是**四源**（OSV/NVD/GitHub/EPSS），pip-audit 只查一个源；③ **不重新发明 CVE 查询** —— 这正是我把它从独立功能收进图谱的原因 |
| **AI 参与判定，安全吗？** | ① 每条判断带**原文行号**（不用信我，自己查）；② AI 挂了**拒判**（fail-closed，绝不输出"可安装"）；③ 规则给确定性、AI 只给意图，**互不覆盖** |
| **下一步？** | 存储层切 RDS/Redis（等券）+ 依赖侧成链 + 更多国际基准对标 |

完整的问答清单在 `docs/汇报问答准备.md`（含依赖检测专项 Q3.5–Q3.7）。

## 十、项目文件在哪

```

modules/asset_graph.py      资产关系图（技能/工具/依赖）
modules/graph_viz.py        关系图可视化（交互版 + 静态 SVG 导出）
modules/compliance_map.py   OWASP Agentic Skills Top 10 映射 + 官方证据
modules/skill_rating.py     标准化评分（权重沿用 SEV_WEIGHT）

samples/                    107 语料 + SCR-Bench + CompoSkill + 13 场景
docs/                       作品报告、讲解手册、汇报问答准备等 20 份
qa/                         自动校验脚本（9 条）
```
