## 四、方法论对标（技术差异化章节的核心）

已获取 CompoSkill 官方开源实现并做**代码级**对比。

### 4.1 对手流水线（CompoSkill / ChainGuard）

1. LLM 一次判完每个技能的 I/O 能力集 + 严重度 + source/bridge/terminal 角色
2. 建能力流图 SCG：边存在当且仅当 `O(a) ∩ I(b) ≠ ∅`，边权 `w = |O(a)∩I(b)| / |I(b)|`
3. k 最短路枚举 源→桥→终，打分 = `∏边权 × r(源) × r(终)`
4. 能力体系 SIGMA = file / network / cmd / memory / config / db / msg / other
5. 威胁分类 T1 数据外发 / T3 记忆篡改 / T5 提权与危险命令 / T6 多 Agent 协同劫持 / T7 资源耗尽

### 4.2 本项目流水线

1. **规则快筛**：8 个能力原子（READ_CRED / EXFIL / EXEC / EVADE / PERSIST / CONTROL / HOST_INFO / DOWNLOAD），
   **区分出站 EXFIL 与入站 DOWNLOAD**
2. **AI 意图分诊**：一次调用同时判「行为意图」（MALICIOUS / SUSPICIOUS / BENIGN）
   与「外发范围」（GENERIC / STRUCTURED / NONE），**每条判断带原文行号**
3. **三要素成链**：能力互补 + **意图闸门**（至少一方恶意/可疑）+ **外发闸门**（提供 EXFIL 的一方 scope 必须是 GENERIC）

### 4.3 五个差异点（表格，逐条写）

| 维度 | CompoSkill/ChainGuard | 本项目 |
|---|---|---|
| 能力判定归属 | 全部由 LLM 一次判断，不可复现、随模型版本漂移 | **规则定能力**（确定性、可复现、零调用成本），AI 只判意图与外发范围两个窄问题 |
| 外发内容结构 | SIGMA 8 类能力中**没有**区分「固定结构 vs 通用内容」 | **独有外发范围闸门**：固定结构（带不走凭据）vs 通用内容（什么都带得走） |
| 证据可核验性 | 无逐行可核验输出 | **每条 AI 判断带原文行号 + 原文片段**，当场能翻原文核对 |
| 失败语义 | 论文未定义 | **fail-closed**：AI 分诊失败绝不给出「可安装」结论 |
| 复算成本 | 每次重跑都需重新调用 LLM | **磁盘缓存命中即零调用**，同一批技能反复体检不花钱 |

### 4.4 一个实测观察（要写，但不要用来贬低对手）

在 3 个官方恶意样本之间建 SCG，**6 条边的边权全部为 1.0**。
说明当技能能力集高度重叠时，边权失去区分度，打分主要靠 LLM 给的 severity 拉开差距。
**写法**：「我们观察到……这提示边权在能力集高度重叠时的区分度有限，
也是本项目选择『规则定能力 + 双重闸门』路线的考虑之一。」

### 4.5 诚实边界（必须写进对标章节）

我们在同样的 13 个场景上，用保守近似跑图搜索口径，得到 0 误报但也漏了 3 个真链路场景——
**这是因为我们只能用规则近似 LLM 的 input_caps 推断，是下界估计，不是对手的真实水平**。
必须写明，不得暗示对手漏报。

### 7.4 必须写明的口径边界

SCR-Bench 原论文指标是**执行后的行为成功率（ASR）**，需要真实 Agent 运行时（Claude Code / Codex）。

### 7.5 顺带修掉的一个真 bug（可写进工程章节）

在跑该基准时发现并修复了一个**误报缺陷**：原 EXEC 规则中的
`` `...` ``（反引号）模式会把文档里的普通函数调用示例
（如 `` `schedule_job(target_id="x")` ``）误判为「执行任意命令」，
导致国际基准 **150/268 个 case 全量误报**。

修复方式：
- 反引号必须内含 shell 命令词或管道/重定向才判定为命令执行；
- `eval(` / `exec(` 前面不能是标识符字符（防 `schedule_exec(` 误匹配）。

修复后：国际基准误报从 150/268 降到 **0/268**，且原有 151 条回归 + 31 项 pytest **全绿**。
这是「用国际公开基准反向体检自己的检测器」的典型案例，很能体现工程严谨性。
