## ⚠️ 先看三条硬性约束（决定一切）

### 约束 1：创新赛没有安徽省赛

校内通知与官方赛程均确认，**省赛只面向实践赛和编程赛**。

| 赛道 | 赛制 |
|---|---|
| 实践赛 | 省资格赛 → **省赛** → 中国总决赛 → 全球总决赛 |
| 编程赛 | 省资格赛 → **省赛** → 中国总决赛 → 全球总决赛 |
| **创新赛** | **初赛 → 中国总决赛 → 全球总决赛**（无省级环节） |

**所以创新赛是国家级赛道，2600+ 支队伍竞争 54 个晋级名额。**

### 约束 2：不用华为技术 = 没有参赛资格

参赛须知第⑤条原文：

> 「创新赛为报名选拔制，**未采用赛题要求的华为技术的队伍不符合参赛资格**。」

**这是资格门槛，不满足则连报名资格都没有。**

### 约束 3：实名认证需 3 个工作日，不能拖

官方流程中「个人实名认证」需**人工审核约 3 个工作日**，之后才能做学生认证。

倒推：

```
11/27（校内最晚报名日）
  −3 个工作日（实名认证审批）
  = 11/24（周二）前必须提交实名认证
```

**今天是 10/17，你有 44 天，但真正的缓冲只有到 11/24。**

## 七、CodeArts 怎么用才算"有效使用"

官方强调要体现它在五个环节的价值：

| 环节 | 本项目可对应的具体任务 |
|---|---|
| 需求理解 | ✅ **已完成**：读 skill_scanner.py，准确报出 32 条规则 / 8 类威胁 |
| **代码生成** | 让它生成新的检测规则（基于 OWASP Agentic Skills Top10 的新威胁类型） |
| 项目构建 | 让它审查 `requirements.txt` 依赖是否安全 |
| **问题修复** | 🔥 **让它审计 `modules/skill_scanner.py` 的正则——专门找误报** |
| 部署上线 | 用它生成部署脚本与云资源开通脚本 |

### 🔥 最推荐的任务：让 CodeArts 审计误报

**理由**：这是**真实需求**，不是表演。

我们刚在 100 个真实良性样本上测出 **6% 误报**，逐条分析过原因
（`model.eval()` 被误判为动态代码执行、MATLAB 的 `startup` 被误判为写自启等）。

**让 CodeArts 独立分析这 6 条误报、给出规则改进建议** —— 这同时做到：
- 满足赛题"问题修复环节使用价值"的要求
- 产出的建议**可以直接用**（不是摆设）
- 报告里可以写「使用 CodeArts 智能体审计检测规则，发现并修复误报 X 条」
  —— 这比任何编造的使用说明都有说服力
