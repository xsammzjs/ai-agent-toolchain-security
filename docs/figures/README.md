## 二、旧图 01~04 为什么不能用（**不是排版问题，是口径冲突**）

这 4 张图是**上一代定位**（单点检测 + 依赖扫描为主）画的，
图上写死的内容与当前对外材料的数字**直接打架**。评委只要看一眼图、对一眼材料，就会发现
数字不一致——这比没有配图更伤。

| 图 | 图上写着的旧口径 | 与当前材料的冲突 |
|---|---|---|
| **01_系统架构图** | 「**25 条规则** / 7 类威胁」「AI（华为云 MaaS）— **只汇总，不判定**」「**6 类链路模板**」 | 现口径是 **32 条规则 / 8 类威胁 / 8 个能力原子 / 7 类链路模板**；且 AI **是判定链路里的闸门**（意图闸门 + 外发范围闸门），不是可选的总结工具 |
| **02_攻击链原理图** | 「**6 类链路模板**」「能力图路径搜索」 | 现口径是 **7 类链路模板**；且方法已从「路径搜索」改为「能力原子 × 意图闸门 × 外发范围闸门」三要素成链 |
| **03_资产图谱示意图** | 旧资产图谱建模（依赖 / 技能 / 工具） | 与新主线（组合风险）不匹配，插进去会让人以为作品主线是资产图谱 |
| **04_扫描流程图** | 「**25 条规则**」「**6 类链路模板**」「线程池并发（实测 **5.75×** 加速）」 | 同 01，规则数与模板数都是旧值；加速比也是旧值——现口径是 **4.45~5.42×**（三次实测区间，来源 `samples/public_bench/_concurrency_bench.json`）。**该图仅存档，其中所有数字都不得引用** |

> 📌 **为什么留着不删**：这 4 张图是项目演进史的一部分（从「单点检测平台」到
> 「组合风险体检站」的过渡证据），删掉反而丢失历史。**归档保留，但打上明确标记。**

## 三、新图 05 / 06 推荐用法

| 图 | 位置 | 用途 | 备注 |
|---|---|---|---|
| **图5** `05_三段式流水线架构图.svg` | 技术方案介绍「整体技术方案介绍」开头 | 一张图讲完三段式流水线：阶段 A 规则快筛（32 条规则 → 8 个能力原子）→ 阶段 B 可核验 AI 意图分诊 → 阶段 C 三要素成链 → 安装决定 | 矢量 SVG，投影放大不糊 |
| **图6** `06_组合风险原理图.svg` | 技术方案介绍「关键模块介绍」开头 / 答辩「组合风险为什么是新的」 | **单点视角 vs 组合视角对照**：config-reviewer（READ_CRED）+ snippet-uploader（EXFIL）两个技能单看都不算严重，组合起来是一条凭据外泄链 | 核心创新点，答辩重点 |

### 插入 Word 的方法

- Word 2016+ 直接支持 SVG：插入 → 图片 → 此设备 → 选 `05_三段式流水线架构图.svg`。
- 若你的 Word 版本不支持：转 PNG——在浏览器打开 SVG 后截图，或用在线转换器
  （**选 2 倍缩放**，答辩投影才清晰）。

### 一致性自检

插图前请核对：图上的数字（32 条规则 / 8 个能力原子 / 7 类链路模板 / 0 报警 / 建议不安装）
与 `docs/模板1填写对照表.md`、`docs/作品报告.md` 的正文**完全一致**。若哪天正文数字变了，
**图也要跟着改**，否则又变成新的口径冲突。
