### 插入 Word 的方法

- Word 2016+ 直接支持 SVG：插入 → 图片 → 此设备 → 选 `05_三段式流水线架构图.svg`。
- 若你的 Word 版本不支持：转 PNG——在浏览器打开 SVG 后截图，或用在线转换器
  （**选 2 倍缩放**，答辩投影才清晰）。

### 一致性自检

插图前请核对：图上的数字（32 条规则 / 8 个能力原子 / 7 类链路模板 / 0 报警 / 建议不安装）
与 `docs/模板1填写对照表.md`、`docs/作品报告.md` 的正文**完全一致**。若哪天正文数字变了，
**图也要跟着改**，否则又变成新的口径冲突。

## 四、目录里其他文件

| 文件 | 说明 |
|---|---|
| `../../qa/check_svg_overflow.py` | SVG 自检脚本（检查 **01~06 全部 6 张图**）：① text 是否超出 viewBox ② **text 是否越过「逻辑所在框」的边线**（跑出自己那个盒子）③ **两段 text 是否真的互相压字**（y 重叠 ≥ 较小字号的 30%）④ **连线是否被后画的不透明矩形盖住而消失**。2026-10-28 起把 01~04 存档图也纳入（它们带了存档水印）。改图后跑一次：`.venv/Scripts/python.exe qa/check_svg_overflow.py`，通过时输出 `RESULT: PASS` |
| `codearts/` | CodeArts 审计过程相关素材（`放这里.md`），非配图 |

> **② 和 ③ 是补出来的，起因都是 04 图。** 2026-10-28 那次改图后脚本一路报
> `RESULT: PASS`，实渲染才发现 04 图有两类问题：**右侧那批灰色代码引用标注越出了
> 所在盒子的右边框线**，并且**压在正文上**（当时读起来像「正文被框线穿过、截断
> 一半」，实际肇事者是标注不是正文）。
>
> 更关键的是：**老脚本的第 ② 项（text 是否溢出所在矩形）其实是死代码** ——
> 它把「背景整幅画布」也当候选容器，于是任何画布内的文字都能被它「包含」，
> 溢出分支永远不执行。等于「文字跑出自己那个盒子」这一整类缺陷，脚本完全看不见。
> 现在 ② 改用「锚点落在哪个最小非背景框里」来定位归属，③ 直接量文字之间的
> 实际重叠 —— **用结果判，不用位置猜**。

> ### 🛑 本守卫不含任何隐式豁免
>
> 判据一律「**用结果判，不用位置猜**」—— 文字是否越框取决于它**实际越没越**、
> 是否与别的文字**实际压没压**，**不取决于它在框内的相对位置**。
>
> 若将来确有为「故意跨框的标注」开口子的需要，必须用**显式属性标注**
> （如 `<text data-allow-overflow="true">`），**不得引入任何位置启发式**
> （例如「锚点在框右侧 N% 以内就放过」）。
>
> **为什么把这条钉死**：2026-10-28 之前，守卫就是这么豁免的 —— 按「锚点是否落在
> 框的右侧 15%」区分「边注标注」与「正文越框」。结果它**豁免的正是肇事者**：
> 04 图那 5 条灰色代码引用标注越框 + 压正文，却因为落在豁免区而全部被放过，
> 于是守卫对一张肉眼可见有 2 处压字的图报 `RESULT: PASS` —— **假安全感**。
> 而且同一段溢出文本，锚点挪 5px 结论就翻转；锚点挪到「探出框宽 80%」也照样放过。
>
> **一个会漏报的守卫，比没有守卫更糟** —— 它让人以为图是安全的。所以宁可严格：
> 要么把元素改对（04 那 5 条标注最后是统一移进框内解决的），
> 要么显式声明例外，**不要让位置启发式偷偷替你决定**。
>
> （注：显式属性 `data-allow-overflow` 目前**尚未实现**，这里只是先把原则钉在
> 文档里 —— 真要开口子时按此办理。）
>
> **② 的适用范围**：② 只判定**有归属**（锚点落在某个面板内）的文字 —— 拿那个面板的
> 边线去比。**完全脱离所有面板、落在画布留白处**的文字会被归属到**整幅画布 rect**，
> 于是 ② 对它退化成 ①（只拿画布边线比）→ 同样不报，**由 ①（viewBox 边界）和
> 第五节的目视清单兜底**。
> （QA 构造测试复现：把 05 里的「读凭据」从能力原子小框挪到画布右侧留白、短到连画布
> 都不超 → ①②③ 三项全部不报、`RESULT: PASS`、EXIT=0。当前 6 张图里这类文字**零条**。）
>
> 另：图里**合法的框外文字**（标题/副标题/阶段标签/页脚，05 与 06 各 9 条）同样归属到
> 整幅画布 rect，对它们只做 viewBox 判定（与 ① 重复）—— **不会误报**。

## 五、改图后怎么自检（脚本查不出来的，得靠眼睛）

脚本能查几何（越界 / 溢出 / 越框 / 遮挡），但**查不出「看起来是不是做坏了」**。
比如 2026-10-28 那次：脚本一路报 `RESULT: PASS`，实渲染一看 04 图的 ⑤→⑥ 箭头
被盒子整个盖住了 —— 这种事只有看图才发现。

**渲染方式**（Playwright + headless Edge，仓库已装 playwright）：

```python
import os
import tempfile
from playwright.sync_api import sync_playwright

# ⚠️ 产物一律写进**临时目录**，别写仓库根 —— 否则照抄这段会在仓库里
#    留下未跟踪的 tmp.html / out.png，与本节「产物不进仓库」自相矛盾。
_OUT = os.path.join(tempfile.gettempdir(), "svg_check")
os.makedirs(_OUT, exist_ok=True)

SVG = "docs/figures/04_扫描流程图.svg"
HTML = ("<!doctype html><html><head><meta charset='utf-8'>"
        "<style>html,body{margin:0;padding:0;background:#fff}</style></head>"
        "<body>" + open(SVG, encoding="utf-8").read() +
        "</body></html>")
_html = os.path.join(_OUT, "tmp.html")
open(_html, "w", encoding="utf-8").write(HTML)
with sync_playwright() as p:
    b = p.chromium.launch(channel="msedge", headless=True)
    pg = b.new_page(viewport={"width": 1000, "height": 560}, device_scale_factor=2)
    pg.goto("file:///" + os.path.abspath(_html).replace("\\", "/"))
    pg.wait_for_timeout(600)
    png = os.path.join(_OUT, "out.png")
    pg.screenshot(path=png, clip={"x": 0, "y": 0, "width": 1000, "height": 512})
    b.close()
print("渲染完成 →", png)      # 产物在系统临时目录，仓库保持干净
```

> ⚠️ **三个坑**（2026-10-28 实测踩过）：
> 1. **别直接 `file://` 打开 `.svg` 截图** —— Playwright 的 `full_page` 截图会卡在
>    `waiting for fonts to load` 直到 30s 超时。**把 SVG 内联进一个 HTML 壳**（如上）
>    就稳定了。
> 2. `full_page=True` 对裸 SVG 不可靠，用 `clip={"x","y","width","height"}` 显式框，
>    局部放大也靠 `clip`（配合 `device_scale_factor=2` 能看清 2px 的线）。
> 3. **产物写临时目录**（`tempfile.gettempdir()`），别写仓库根 —— 否则照抄会在
>    `git status` 里冒出 `?? tmp.html` / `?? out.png`。
>
> 渲染产物放临时目录，**不要进仓库**。

**建议的目视清单**：① 连线/箭头是否都在、② 每个框是否完整没被裁、③ **标注/正文**
有没有越过框的边线、④ 标题与正文有没有互相压字、⑤ 水印在不在画布内且不压图形。

> ③ 为什么要写「标注/正文」而不是只写「正文」：04 图那次的肇事者是**右侧那批
> 灰色代码引用标注**（`engine._prepare_files()` 等），它们锚在 x=660、盒右缘 670、
> 黄色旁注框从 700 开始 —— **可用空间不足，必然越框**。正文反而是安全的
> （实测右端 648.6，在框内）。只查正文会漏掉真正的肇事者。
>
> 修法也是按根因统一处理的：2026-10-28 把那 5 条标注**统一移到各自盒子的标题行、
> 右对齐到框内右缘 x=666**，而不是逐个躲重叠 —— 改完浏览器实测「越框 0 处、
> 压字 0 对」，脚本也能自己验了。
