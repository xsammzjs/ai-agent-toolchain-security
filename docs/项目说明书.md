# AI 技能组合风险体检站

> 检测 AI Agent 技能包（Skill）风险的静态分析工具，
> 核心能力是**多技能组合风险关联分析**与**可核验 AI 分诊**。

**在线演示**：https://xsammzjs-ai-agent-toolchain-security-main-w3d8io.streamlit.app
**代码仓库**：https://github.com/xsammzjs/ai-agent-toolchain-security

---

## 一、这个项目解决什么问题

### 1.1 背景：AI 正在安装软件包

过去软件工程装依赖（pip install、npm install），
现在 AI Agent 装 **Skill**——本质上是同一件事，
但安全工具完全没跟上。

```
传统软件：pip install requests   ← 有 pip-audit / Snyk / Trivy 管着
AI Agent：安装一个 Skill         ← 没有专门工具管
```

Skill 就是一个文件夹，里面放着 `SKILL.md`（指令）+ 可能还有脚本。
**AI 会照着这些指令执行你不知道会发生什么。**

### 1.2 真实威胁已经发生

| 事实 | 来源 |
|---|---|
| 1,184 个恶意 Skill，造成 **24.7 万次安装** | 2026 年 ClawHavoc 事件 |
| **36.82%** 的公开技能含提示注入 | Snyk 审计 |
| 98,380 个技能中 4,287 个静态可疑 | USENIX Security 2026 论文 |

**规模比 PyPI 早期蠕虫事件更大。**

### 1.3 传统工具为什么不够

现有工具（Snyk ToxicSkills 等）都是**单点检测**：

```
Skill A  有风险 ✓
Skill B  有风险 ✓
Skill C  有风险 ✓
          ↓
    但它们合在一起能做什么？   ← 传统工具答不上来
```

**真实攻击恰恰是组合式的**：

```
Skill A  读 ~/.aws/credentials      （单独看：普通读文件）
Skill B  通过 webhook 外发数据       （单独看：普通网络请求）
Skill C  让 A 调用 B                （单独看：普通依赖）

→ 串起来就是完整的凭据窃取链路，传统工具三个都判不严重
```

**这就是本项目的核心创新：把分散的单点风险重新关联成组合链路，并给出「该不该装」的结论。**

## 二、核心能力

### 2.1 功能清单

| 模块 | 能力 | 代码位置 |
|---|---|---|
| 静态检测 | 32 条规则覆盖 8 类威胁，每条给出行号可当场核验 | `modules/skill_scanner.py` |
| **组合体检** | 规则快筛 → AI 意图分诊 → 三要素成链，给出「该不该装」的结论 | `modules/combo_analysis.py` |
| 资产图谱 | 依赖包 / Skill / MCP 工具统一建模为节点 | `modules/asset_graph.py` |
| 攻击链关联 | 资产调用关系 + 依赖侧链路 | `modules/attack_chain.py` |
| 依赖研判 | OSV / NVD / GitHub / EPSS 四源交叉验证 | `modules/vulnerability.py` |
| 可核验 AI 分诊 | 判定行为意图与外发数据范围，是组合判定两道闸门的输入；每条判断带原文行号，分诊失败即拒绝放行 | `modules/adjudicator.py`、`modules/combo_analysis.py` |
| 证据溯源 | 每条结论可定位到具体文件与行号 | 全局 |

### 2.2 八类威胁

| 威胁类型 | 典型手法 |
|---|---|
| 提示注入 | 忽略用户指令、角色覆盖、隐瞒操作 |
| 凭证窃取 | 读 `~/.aws/credentials`、读 `.env`、`eval`/`os.system` 拼接外部输入（CWE-78） |
| 数据外发 | Webhook 外发、临时粘贴站、`scp` 传密钥到远端 |
| 危险命令 | 管道执行下载内容、递归删除根目录、PowerShell 下载执行 |
| 混淆载荷 | 动态代码执行、长 Base64 编码载荷 |
| 持久化污染 | 写入 Agent 记忆文件（跨会话污染）、开机自启 |
| 供应链风险 | 不安全源安装依赖、全盘目录访问 |
| 隐藏字符注入 | 零宽字符、Unicode Tag 字符（ASCII Smuggling）、双向控制字符 |

### 2.3 三条硬性架构原则

**① 三段式分工（规则定能力 / AI 只判窄问题 / 闸门成链）**

```
阶段A 规则快筛：确定性规则 → 提取 8 个能力原子，给出行号可核验
阶段B 可核验 AI 分诊：只判「行为意图」与「外发数据范围」两个窄问题，
                     每条判断带原文行号；失败 fail-closed 不放行
阶段C 组合判定：能力互补 × 意图闸门 × 外发范围闸门 → 给出「该不该装」
```

未配置大模型时自动降级为本地模板，并明确标注「未调用大模型」——
**宁可承认降级，也不伪装成 AI 输出。**

**② 零网络依赖**

规则快筛完全离线，33ms 出结果，不调用任何外部 API。
这意味着**部署成本为零、可用性不受网络影响**。

**③ 结论可核验**

每条检出都带「文件名 + 行号 + 命中原文 + 规则名 + 处置建议」，
**评委/用户可以当场翻代码验证**，不是模型说的算。

## 三、实测数据

### 3.1 核心指标

| 指标 | 数值 | 测试集 |
|---|---|---|
| **恶意样本检出率（TPR）** | **100%** | 7 个 Snyk 真实恶意样本 |
| **真实良性语料误报率（FPR）** | **2.0%** | 100 个真实科研类技能 |
| **特异度（正确放行率）** | **98.0%** | 同上 |
| **单次扫描耗时** | **33 ms** | 纯本地规则引擎 |
| **回归测试** | **151 条断言全绿** | — |

### 3.2 误报优化过程（本项目最有价值的部分）

**初始误报率 58.6%** —— 超过一半的正常技能被误判。

用华为云码道 CodeArts 做三轮规则审计后降到 **2.0%**，
**期间恶意检出率始终保持 100% 无回退**。

典型误报与根因：

| 技能文档中的正常写法 | 被误判为 | 根因 |
|---|---|---|
| `model.eval()` | 动态代码执行 | HuggingFace 标准 API |
| `startup/shutdown tasks` | 写入开机自启 | MATLAB 术语 |
| `uv pip install pybids` | 供应链风险 | 常规依赖安装 |
| `does not expose webhooks` | 数据外发通道 | 原文说的是「不」暴露 |

**根因不是"规则太多"，而是把「文档在描述怎么做」当成了「技能在执行什么」。**

完整记录见 `docs/CodeArts审计实践.md`（含一次把误报从 6% 改到 33% 的真实事故）。

### 3.3 数据集

| 语料 | 样本数 | 内容 |
|---|---|---|
| Snyk `toxicskills-goof` | 7 | 真实恶意技能（含完整正文） |
| K-Dense-AI `scientific-agent-skills` | 100 | 真实科研类良性技能（含完整正文） |
| USENIX Security 2026 数据集 | 157 | 恶意样本元数据（正文已被论文方封禁删库） |

**合计 107 个含正文的真实样本**，均来自公开研究仓库，仅用于防御性安全研究，
**不执行任何样本内容**。

## 四、代码结构

```
main.py                界面入口（5 个功能）
config.py              全局配置
modules/
  engine.py            扫描调度
  parser.py            7 种依赖清单格式解析
  vulnerability.py     四源漏洞研判 + 并发加速
  skill_scanner.py     32 条静态检测规则        ← 核心
  combo_analysis.py    8 个能力原子 + 7 类链路模板三要素成链 ← 核心创新
  attack_chain.py      资产调用关系与依赖侧链路
  asset_graph.py       资产图谱构建
  adjudicator.py       可核验 AI 分诊（意图 + 外发范围，带行号证据）+ 闸门
  store.py             存储抽象层（本地/华为云可切换）
  storage/huawei.py    华为云 RDS + Redis 实现
  demo_mode.py         离线演示模式（答辩保障）
  report.py            报告生成
docs/                  项目文档
samples/               评测脚本与语料下载
tests/test_regression.py  151 条回归测试
```

**代码规模**：9,786 行 Python（交付代码 9,211 行 = `modules/` + `views/` + `launcher/` + `main.py` + `config.py` + `start.py`，回归测试 575 行 = `tests/test_regression.py`，不含评测脚本）

### 数据流

```
用户上传/演示样例
      ↓
parser.py        解析依赖清单 + Skill 目录结构
      ↓
skill_scanner.py 32 条规则逐条匹配 → 检出风险点（含行号）
      ↓
combo_analysis.py 阶段A 规则快筛 → 8 个能力原子
      ↓             阶段B AI 意图分诊（意图 + 外发范围两道闸门）
      ↓             阶段C 三要素成链 → 7 类链路模板 →「该不该装」
      ↓
asset_graph.py   统一资产视图（依赖 + Skill + 工具）
      ↓
adjudicator.py   阶段B AI 意图分诊（意图 + 外发范围两道闸门）+ 单点页研判建议
      ↓
report.py        生成报告
```

## 五、怎么运行

```bash
# 安装依赖
pip install -r requirements.txt

# 启动界面
streamlit run main.py
```

### 运行评测（可复现全部指标）

```bash
python samples/fetch_real_samples.py    # 下载评测语料
python samples/run_real_eval.py         # 恶意样本检出率
python samples/run_corpus_eval.py       # 真实语料误报率
python samples/run_bench_eval.py        # 威胁类型分布分析
python samples/verify_codearts_suggestions.py  # CodeArts 建议验证
python tests/test_regression.py         # 151 条回归测试
```

**所有指标均可本地纯离线复现，不依赖外部 API。**

## 六、差异化优势

| 维度 | 现有工具 | 本项目 |
|---|---|---|
| 单技能风险识别 | ✅ | ✅ |
| **跨技能攻击链** | ❌ | ✅ |
| **依赖 + Skill + 工具统一资产视图** | ❌ | ✅ |
| 部署依赖 | 部分需联网/付费 | **规则侧完全离线、零调用成本**（AI 分诊按需启用，命中缓存时同样零调用） |
| 结论可核验性 | 模型推测 | **行号 + 规则名，可当场核验** |

**竞品调研（跨赛道旁证）**：调研全国大学生信息安全竞赛（信安国赛，
与华为 ICT 大赛为两个独立赛道，此处仅作技术方向的平行参考）45 个一等奖，
其中 5 个是 Agent 安全方向（SkillLens、MCP-Sentinel、TraceShield、ClawGuard、
枢盾 MCP Guardrails），**全部为单点检测，无一做跨资产关联**。

> 表述限定：以上结论限于「信安国赛国奖一等奖 + 已知同赛道工具」这一调研范围，
> 且属**跨赛道旁证**，不可作为华为赛获奖依据，
> 更不可夸大为「全球首创」。
