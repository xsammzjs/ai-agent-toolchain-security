**作品报告**

> 作者：合肥大学 网络与信息安全创新实验室
> 版本：v5.0（2026-10-26 聚焦化：定位收敛为 AI 技能供应链安全检测）

## 摘要

AI Agent 技能（Agent Skill）已成为一类新兴的软件供应链资产。2026 年 2 月 Snyk 发布的 ToxicSkills 研究显示，在其扫描的 3,984 个技能中，**36.82%（1,467 个）至少含有一个安全缺陷，13.4%（534 个）含严重缺陷**，其中 76 个被人工确认为恶意技能。与传统软件供应链不同，Agent Skill **天然继承 AI Agent 的全部权限**——shell 访问、文件系统读写、环境变量中的凭据、以及通过即时通讯与邮件通道外发数据的能力。

针对这一问题，现有工具的检测范式存在结构性局限：**它们全部是"单点检测"**——逐个技能独立打分，输出风险等级列表。当攻击者将恶意行为分散在多个看似无害的技能中时，单点检测会得出"每个技能最多是中危"的结论，从而漏掉真正的系统性威胁。

本作品提出**跨技能攻击链关联分析**方法：从静态规则引擎的确定性检测结果中提取"危险能力"，建立能力索引与资产图谱，在此基础上进行图路径搜索，将分散的单点风险连接为完整的攻击链路。实测表明，本方法可在**完全离线**的前提下识别出单点检测无法发现的跨技能攻击链。

**关键词**：AI Agent 安全；技能供应链；提示注入；攻击链关联；确定性检测

## 第一章 研究背景

### 1.1 问题背景

AI Agent 正在从"对话工具"演变为"能动手干活的执行者"。为让Agent 掌握特定技能，开发者社区形成了 Agent Skill 这种形态的扩展包——本质是一个 `SKILL.md` 指令文件，Agent 读取后获得执行某类任务的能力。

这类扩展带来了传统软件供应链所不具备的风险特征：

| 维度 | 传统包生态（2015-2020） | Agent Skills（2026） |
|---|---|---|
| 提权攻击 | 需借助依赖混淆等手段 | **默认即高权限**，直接继承 Agent 全部权限 |
| 提示注入 | 无对应概念 | **天然存在**，自然语言即可绕过代码级检测 |
| 持久化 | 可通过修改配置文件 | **可写入 Agent 记忆文件，跨会话存活** |
| 发布门槛 | 需包管理审核流程 | **一个 Markdown 文件 + 一周龄的 GitHub 账号** |

Snyk 的研究量化了这一风险：已确认的恶意技能中，**100% 包含传统恶意软件模式，91% 同时使用提示注入**——这一组合恰好能同时绕过 AI 安全过滤与传统恶意软件扫描器。

### 1.2 现有方案的局限

本作品调研了当前主流方案，发现其共性局限：

| 方案 | 覆盖范围 | 核心局限 |
|---|---|---|
| Snyk ToxicSkills / mcp-scan | Skill 单点检测 | 单点判定，不做跨技能关联 |
| SkillSpector-static | 静态规则 | 同上 |
| Cisco-local-behavioral | 运行时行为 | 同上，且需实际运行 |
| 传统供应链工具（Snyk Dependabot / pip-audit / Trivy） | 依赖包漏洞 | **完全不覆盖 Agent Skill** |

**共性局限：全部是"单点检测"——回答"哪个技能危险"，不回答"这些技能凑在一起会造成什么后果"。**

### 1.3 本作品的定位

本作品不重复造单点检测的轮子，而是**在确定性检测的基础上补上关联分析这一层**：

```
已有能力（复用）：静态规则引擎 → 每个技能的风险等级
本作品新增：      能力图 + 路径搜索 → 跨技能攻击链的识别与还原
```

## 第二章 作品内容

### 2.1 总体架构

系统采用四层架构，每层职责单一、依赖单向向下：

| 层 | 职责 | 关键约束 |
|---|---|---|
| ① 接入层 | 接收 ZIP/RAR 技能包、依赖清单 | 拒绝路径穿越（zip slip） |
| ② **检测层** | 32 条静态规则、四源交叉验证、攻击链搜索、资产图谱 | **判定唯一来源，结论必须可追溯到行号** |
| ③ **研判层** | 基于已判定证据做汇总、解释、处置建议 | **不得改写判定，不得凭空新增风险** |
| ④ 存储层 | 扫描历史、资产图谱、查询缓存 | 抽象接口，本地/云端可切换 |

> **架构图**：见 `docs/figures/01_系统架构图.svg`

**最关键的设计约束**在② 与 ③ 之间的分工：

- **检测层给出判定**：命中哪条规则、在第几行、什么严重度——全部是确定性事实，可当场核验
- **研判层只做归纳**：把分散的检测结果综合起来回答"最该先处理哪个、为什么、怎么做"

这一分工在代码层面被强制约束（见 2.4 节），而非仅写在文档里。

### 2.2 静态规则检测（检测层）

#### 2.2.1 规则体系

32 条规则覆盖 8 类威胁，威胁分类参考 OWASP Agentic Skills Top 10 与 Snyk ToxicSkills 的公开研究：

| 类别 | 规则数 | 代表规则 | 典型严重度 |
|---|---|---|---|
| 提示注入 | 5 | 忽略指令型注入、角色覆盖型注入、隐瞒用户型指令、持续输出型注入、规则覆盖型指令 | 高危 |
| 凭证窃取 | 3 | 敏感凭据路径读取、环境变量枚举、命令注入风险 | 中危 |
| 危险命令 | 6 | 递归删除命令、管道执行下载内容、解码执行混淆内容、Shell 拼接执行、下载后提权执行、PowerShell 下载执行 | **严重** |
| 数据外发 | 7 | 临时粘贴站外发、curl/wget 携带主机信息外发、Webhook 外发通道、外发转发通道、scp/rsync 传输凭据文件、IP 直连 URL、外发动词模式 | 高危 |
| 混淆载荷 | 3 | 动态代码执行、长 Base64 字符串、十六进制转义串 | 高危 |
| 持久化污染 | 2 | 写入 Agent 记忆文件、写入开机自启配置 | 高危 |
| 供应链风险 | 4 | 索取过高系统权限、全盘或家目录大范围访问、不安全源安装依赖、明文 HTTP 下载 | 高危 |
| 隐藏字符注入 | 1 | 零宽字符 / Unicode Tag 字符 / 双向控制字符（ASCII Smuggling） | **严重** |

> 合计 31 条：上表 30 条来自 `RULE_TABLE` 正则规则表，隐藏字符注入是独立的
> Unicode 字符检测通道；另有 1 条模块级组合规则「凭证窃取完整链路」
> （同文件内命中读凭据动作 AND 命中实际外发通道 → 判严重），归入凭证窃取类别。
> **总计 32 条规则、8 类威胁。**

#### 2.2.2 两个增强检测

**隐藏 Unicode 注入**：检测编辑器不可见、但模型可完整解析的字符（如 Unicode Tag 字符 U+E0000 区间）。攻击者可借此把恶意指令伪装成正常文本， humans 肉眼无法察觉而模型会照常执行。

> **实战验证**：在 Snyk 官方样本 `gemini/skills/testing-guidelines` 中，该检测命中 **171 处**。该样本正是 Snyk 报告中提到的 **ASCII Smuggling** 手法（利用 `ascii-smuggler` 工具把 Unicode 标签编码进正常文本）。

**跨行组合规则**：单独出现"读取敏感文件"或"外发通道"都可能是正常操作；但**两者同时出现**即构成完整的凭证窃取链路。该规则要求跨行匹配，显著降低误报。

### 2.3 跨技能攻击链关联（核心创新）

#### 2.3.1 方法

单点检测的局限可以用一个具体场景说明：

```
Skill A（读 .env 凭据）    单点判定 → 中危
Skill B（往 pastebin 发数据） 单点判定 → 高危
─────────────────────────────────────────────
传统工具的结论：最严重的是高危。
真实情况：A + B 串起来 = 密钥被发送到境外站点 = 严重
```

本作品的检测方法分三步：

**第一步：能力提取**
从规则检测结果中提取"危险能力"（6 类能力原子）：
`READ_CRED`（读凭据）、`EXFIL`（外发数据）、`EXEC`（执行命令）、
`EVADE`（规避检测）、`PERSIST`（长期驻留）、`CONTROL`（劫持 AI 行为）

**第二步：能力索引**
建立「能力 → 提供者」与「能力 → 消费者」双向索引，使跨技能检索成为可能。

**第三步：图路径搜索**
按 6 类攻击链模板（凭据外泄、驻留+外发、命令执行+外发、AI劫持+读凭据、规避检测+执行、驻留+AI劫持）在能力图上搜索路径。跨技能分布的链路额外加权（+5），因为它更难被人工发现。

> **原理图**：见 `docs/figures/02_攻击链原理图.svg`

#### 2.3.2 实战验证

用内置的三个"协同作案"演示样例（单看均无害）：

```
单看 demo-env-collector        → 中危（读个配置而已）
单看 demo-telemetry-reporter   → 高危（发个数据而已）
──────────── 传统工具到此为止 ────────────
关联分析 → 【严重】凭据外泄链路 · 风险分 14
      读取敏感凭据  ← demo-env-collector      SKILL.md:6 [敏感凭据路径读取]
      向外传输数据  ← demo-telemetry-reporter SKILL.md:6 [外发转发通道]
```

每一环节都能追溯到原文行号与命中规则，评委可当场核验。

### 2.4 AI 研判层的职责边界（关键设计）

本作品 2026-10-05 曾移除全部 AI 功能，理由是"大模型输出是自然语言，无法作为可复现的证据"。这一判断对"让 AI 做检测"是成立的，但对"让 AI 做归纳"并不成立。

本作品的解法是**给 AI 换位置**，而非恢复旧方案：

| | 让 AI 检测（旧方案，已弃） | AI 做研判（本作品） |
|---|---|---|
| 输入 | 原始待判定文件 | **规则已判定的证据** |
| 输出 | 风险等级（自然语言） | 汇总、解释、处置建议 |
| 可核验 | ❌ 出错无法追溯 | ✅ 每条引用规则名+行号 |
| 是否改判定 | 是 | **绝不允许** |

**这一约束写进了代码**，而非仅写在文档：

```python
# modules/adjudicator.py
def assert_ai_not_judging(payload: dict) -> None:
    """守卫：确保 AI 输入只包含「已判定的证据」，不包含原始待判定内容"""
    required = ("verdict", "findings", "source")
    missing = [k for k in required if k not in payload]
    if missing:
        raise ValueError(f"AI 研判输入缺少必需字段 {missing}。")
```

违反约束时直接抛错而非静默通过——让越界行为暴露。该边界已由回归测试锁定（断言 AI 层不含任何检测函数）。

**降级策略**：未配置 MaaS 时自动降级为本地模板生成研判，界面明确标注"未调用大模型"，不伪装成 AI 输出。

### 2.5 资产图谱

把三类异构资产统一建模为节点，关系建成边：

| 节点类型 | 举例 | 典型关联 |
|---|---|---|
| 依赖资产 | django 3.2.1 | 被技能读取 |
| 技能资产 | env-collector（高危） | 调用依赖、调用工具 |
| 工具资产 | pastebin（外带通道） | 被技能调用 |

这一设计直接对应赛题 1 要求的「多模态异构数据资产统一识别与资产标识」。攻击链在图上表现为**跨资产的攻击边**，例如：

```
demo-env-collector ──调用──▶ demo-telemetry-reporter（凭据外泄链路）
```

> **示意图**：见 `docs/figures/03_资产图谱示意图.svg`

### 2.6 存储抽象层

定义 `StorageBackend` 抽象接口，提供两种实现：

- `LocalStore`：纯标准库、零依赖、离线可用（默认）
- 华为云 RDS + Redis：赛题 1 要求项

**业务代码只依赖接口，不依赖具体实现**。未配置云端时自动回落本地，功能完全不受影响。这保证了同一套代码既能本地运行，也能云端部署。

### 3.3 真实数据暴露的缺陷及修复

真实样本的引入暴露了一个**人工样例无法暴露的设计缺陷**：

**现象**：样本 `agents/skills/vercel` 使用 `paste.c-net.org` 外带主机信息，该域名不在关键词表中，导致整个样本漏检。

**根因**：靠**穷举域名**的检测方式必然漏检——攻击者可随意注册一次性外带站点。

**修复**：新增 2 条通用规则（临时粘贴站外发、curl/wget 携带主机信息外发），
规则体系从仅含关键词匹配，升级为**通用模式 + 语义组合**两类检测并存的形态：

| 规则 | 作用 |
|---|---|
| 临时粘贴站外发 | 匹配 `paste\.[a-z0-9\-]+\.[a-z]{2,}`、`hastebin.com`、`rentry.co` 等外带站**通用模式** |
| curl/wget 携带主机信息外发 | 识别 `curl/wget --data` 与 `uname/hostname/env/.env/credentials` 的**外发语义** |

**修复效果**：恶意样本检出从 4/5 提升到 **5/5**。

这一过程本身说明：**在真实数据上做评测不是形式工作，它确实能发现设计层面的问题。**

### 3.4 性能测试

四源漏洞研判（OSV/NVD/GitHub/EPSS）在原实现中为串行执行。11 个真实 GitHub 项目的重测耗时 **1,035 秒**，且因网络限流反复出现查询失败重试。

**并发化改造**：在依赖粒度采用线程池并发，实测（ComfyUI 项目 8 个依赖，已清空 API 缓存的真实网络请求）：

| 模式 | 耗时 | 检出漏洞数 |
|---|---|---|
| 串行 | 8.0 s | 22 条 |
| 并发（8 线程） | 1.4 s | 22 条 |
| **加速比** | **5.75×** | — |

**结果一致性**：两种模式的漏洞 ID 集合完全相同——**并发只改变速度，不改变结论**。

> **流程图**：见 `docs/figures/04_扫描流程图.svg`

### 3.5 稳定性与降级测试

答辩现场存在断网或外网限流的可能。本作品设计了三层降级：

| 层级 | 机制 | 行为 |
|---|---|---|
| L1 | 查询失败不缓存 + 重试 1 次 | 避免把失败结果当"零漏洞" |
| L2 | 网络连通性探测 | 界面提前预警 |
| L3 | 4 个预置演示场景 | 完全离线可跑完整演示流程 |

**核心原则**：**宁可明确告知"数据源不可用，已降级"，也不显示零漏洞**——后者会让评委误以为系统损坏。

同时系统会在界面顶部以红字披露查询失败次数，避免"静默漏检"。

## 第四章 创新性说明

### 4.1 主要创新：跨技能攻击链关联

**现有方案均为单点检测**，本作品提出并实现了关联分析层，在能力图上进行路径搜索，将分散的单点风险还原为完整攻击链。

**调研范围内的同赛道作品全部为单点检测**：本作品调研了**全国大学生信息安全竞赛**
（信安国赛，与本赛事为两个独立赛道的平行参考）45 个一等奖作品名单，
其中 5 个属于 Agent/MCP 安全方向——**SkillLens**（哈工大）、**MCP-Sentinel**、
**TraceShield**、**ClawGuard**（南开）、**枢盾 MCP Guardrails**——
**均实现单技能内的风险点枚举，未实现跨资产攻击链关联**。

> **本作品的差异**：单点检测的固有盲区是「多个各自不严重的技能组合后构成完整攻击」。
> 本作品在检测层之上构建能力图（能力原子 → 提供者/消费者双向索引），
> 按攻击链模板做图上路径搜索，将分散风险还原为完整链路判定。
>
> **调研范围声明**：上述结论基于「信安国赛 45 个国奖一等奖 + 已知同赛道工具」
> 这一范围。Agent 安全方向整体仍处早期，各平行赛道的头部作品水平接近，
> 故该结论可作为技术方向新颖性的旁证；本作品不主张「全球首创」。

**可验证的差异**：本项目对同一组样本同时输出「单点判定」与「关联判定」两套结果，
可直接对比（见 `modules/attack_chain.py` 与 Demo 的「组合风险分析」视图）。

### 4.2 差异化优势

| 维度 | 单点检测工具 | 本作品 |
|---|---|---|
| 单技能风险识别 | ✅ | ✅ |
| **跨技能攻击链** | ❌ | ✅ |
| **资产统一视图**（依赖+技能+工具） | ❌ | ✅ |
| **部署依赖** | 部分需联网/付费 | **完全离线，零调用成本** |
| **结论可核验性** | 模型推测 | **行号 + 规则名，可当场核验** |
| **AI 的角色** | 直接下判定（不可核验） | **仅做汇总，不改判定（代码强制）** |

### 4.3 原创性合规声明

本作品遵循赛题「禁止将其他赛事作品不加改进参赛」「严禁盗用现成成熟技术」的要求：

1. **代码原创**：核心 6,514 行 Python（`modules/` + `main.py` + `config.py`）均为本项目实现，无第三方项目代码复制；另有回归测试 554 行。
2. **数据引用合规**：所有威胁数据均标注来源出处——
   - ClawHavoc 事件（1,184 个恶意技能、24.7 万次安装）
   - Snyk ToxicSkills 研究（3,984 个样本、36.82% 含缺陷）
   - OWASP Agentic Skills Top 10威胁分类
   - 评测样本来自 Snyk 官方公开样本库
3. **威胁分类为公开研究共识**：检测"忽略指令""读取 .env"这类模式，是任何检测工具都必须覆盖的通用攻击手法。本作品自行实现了正则规则集、跨行组合规则、隐藏 Unicode 检测与攻击链搜索算法。
4. **未盗用他人实现**：攻击链分析为本作品提出的方法，未参考任何同类实现。
