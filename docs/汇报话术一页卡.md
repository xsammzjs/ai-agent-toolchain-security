## 🎤 主汇报（3.5 分钟，照念）

> 「老师好，我们汇报一下 ICT 大赛创新赛赛题一的进展。
>
> **先说这个项目是什么**：我们做的是一个 **AI 技能组合风险体检站**——
> 多技能组合风险的关联分析与**可核验 AI 分诊**。
> 它分两层：
> **第一层是 AI Agent 装的技能包**（一个 `SKILL.md` 文件就是一个技能），
> **第二层是传统代码依赖包**。
> 两层都做单点检测，但重点在把它们放在一起做**组合风险分析**。
>
> **为什么现在要做这个**：
> AI Agent 现在靠装技能获得能力，但技能包**继承 Agent 的全部权限**——
> shell、文件、环境变量里的凭据全都能碰。
> 而且发布门槛极低：**一个 Markdown 文件 + 一周龄的 GitHub 账号**。
> Snyk 去年扫了 3,984 个公开技能，**36.82% 至少含一个安全缺陷**。
> 关键是：传统工具（Snyk Dependabot、pip-audit、Trivy）
> **只会去查 requirements.txt，根本不解析 SKILL.md**。
>
> **我们的五个功能**：
> 🛡️ **AI 技能安全检测** —— 32 条规则扫技能包，命中就给原文行号和规则名；
> 🧬 **组合体检** —— 这是我们的核心原创点；
> 📦 **依赖漏洞检测** —— 四个权威漏洞库交叉验证，给置信度评级和修复优先级；
> 🔗 **资产关联分析** —— 依赖 / 技能 / 工具统一到一张资产图谱；
> 🎬 **离线演示** —— 现场断网也能演。
>
> **第二个功能（组合体检）到底解决什么，我举个例子**。
> 假设 Agent 装了三个技能：
> A 读 `.env` 拿密码，单看判**中危**；
> B 做格式化输出，单看判**安全**；
> C 往 telemetry 上报数据，单看判**高危**。
>
> **单点检测到此为止 —— 结论就是 A 中危、B 安全、C 高危。**
> 但真实情况是：A 读到的密码，被 C POST 出去了。
> **这是一条完整的凭据窃取链路，每个技能单看都不算最严重。**
>
> 传统工具和所有同赛道工具（SkillLens、ClawGuard、MCP-Sentinel）
> **全都停在单点**。
>
> 我们怎么做的：**三段式流水线**——
> ① **规则快筛**：32 条确定性规则把技能翻译成 **8 个能力原子**（纯离线、零模型调用）；
> ② **AI 意图分诊**：判「行为意图」和「外发数据范围」两道闸门，
> 每条判断都带原文行号，当场可核验；
> ③ **三要素成链**：命中 **7 类链路模板**。
> 最后给出的不是一张风险清单，而是一个结论：**这批技能该不该装**。
> 规则那一段不新增任何检测逻辑，但 **AI 是判定链路里的闸门，不是事后总结**。
>
> **现状**：32 条规则 / 8 类威胁、107 个真实公开样本评测
> （检出 100%、误报 2.0%、特异度 98%）、单次扫描 33 毫秒、
> 151 条回归断言全绿、语料随仓库开源、14 项第三方复现校验全绿、
> 在线 Demo 已上线。
>
> **赛题三条技术要求**：第一条用 CodeArts 码道开发，我们已经用它对
> 全部检测规则做了三轮审计，产出 11 处误报边界修正和 2 个 P0 级漏报修复，
> **这条是完成的**。第二三条是要关联 RDS、Redis 存扫描记录和缓存结果、
> 把作品部署到华为云公网、再申请大模型 API 供 AI 研判调用，
> **这三件事都需要代金券**。我们 10 月中下旬报名已经完成，
> 官方赛题页也写明代金券申请 10 月才启动，具体发放方式、额度和有效期
> 以组委会最终通知为准，现在账户还没到账，所以云上这部分还没法动手。
>
> **代码这边随时可以接上云资源**，业务逻辑一行不用改，只换数据源和部署位置。
>
> 想请老师帮忙问一下对接老师：代金券大概什么时候能发放、额度够不够开这三个资源？
> 另外赛题要求里有一条是『基于已有智能体和 Skills 关联 RDS、Redis 快速开通创建』，
> 想请教这个开通流程是走我们自己的账号，还是有指定的统一入口或者对接人？
> 我们好提前把步骤准备好。」

## 🔍 六个追问预案

| 老师问 | 你答 |
|---|---|
| 「依赖漏洞这块不是已经有 Snyk 了吗？」 | 「对，那条赛道确实卷死了。我们**没把依赖漏洞当原创点**——它的定位是**并列的第二个检测能力**，不是附属品。但我们和 Snyk 有两处实质区别：**置信度评级**（按 NVD/GitHub/OSV 权威性加权，不是取平均）、**EPSS 驱动的优先级**（CVSS 高不等于马上要修，要看 30 天内实际被利用的概率）。而 Snyk 那些工具**既不解析 SKILL.md，也没有任何关联分析的概念**——那才是我们真正的新增能力。」 |
| 「这跟市面上的工具有什么区别？」 | 「传统供应链工具只查依赖包的已知漏洞，完全不管技能包。同赛道的 SkillLens、ClawGuard、MCP-Sentinel、TraceShield 全是**单点检测**——查出这个 Skill 有 13 个风险点就结束了。我们做的是**跨资产关联**：回答的不是「哪个技能危险」，而是「**这些凑在一起会造成什么后果**」，并给出可核验的攻击路径、真实危害和处置建议。」 |
| 「你现在具体做到哪一步了？」 | 「代码完整可跑，五个功能都通了：AI 技能安全检测、组合体检、依赖漏洞检测、资产关联分析、离线演示。本地 32 条规则、107 个真实样本评测都过了，14 项第三方复现校验全绿，Demo 已上线。只差换数据源和部署位置。」 |
| 「代金券还没到，你们自己不能先弄吗？」 | 「赛题的部署要求是『作品在华为云上的快速部署』，评委复现时会看是不是真跑在华为云上。没有资源就开不出来，所以想问一下券的时间，我们好卡着 12 月初赛提交节点排期。」 |
| 「这个是不是套了个正则就跑？」 | 「规则部分确实有 32 条正则，但真正花功夫的是三件事：**误报治理**（100 个真实科研 Skill 里曾有 58 个误报，根因是规则分不清『文档在描述』和『技能在执行』，这是静态正则的天花板——过程记录见 `docs/CodeArts审计实践.md`）；**组合判定层**（8 个能力原子 + 7 类链路模板三要素成链 + AI 意图/外发范围两道闸门 + 依赖/技能/工具统一到一张资产图谱）；**AI 工具的工程化使用**（三轮 CodeArts 审计，1 条建议被我否决，第二轮它自查出第一轮引入的 P0 缺陷导致 `os.system` 检测失效，有一次我的正则改动让误报从 6% 飙到 33%，单元测试抓不到，是真实语料抓出来的）。」 |
| 「这个项目能干什么用？」 | 「给企业 AI 应用的准入审计用。AI Agent 接入 CI 之前，先扫一遍它要装的技能包和依赖包，出一个带行号的清单给安全团队签字。现在的痛点是：AI 应用上线太快，传统 SCA 工具完全看不到技能包这一层，而技能包恰恰是权限最高、门槛最低的一层。」 |

## ⚠️ 讲的时候注意

1. **开场讲「检测两类资产 + 找出组合风险」**。
   不要说「双链」「两条腿」「左手右手」。
2. **五个功能都要露一面**，但重点在 🧬 组合体检：
   Skill 安全检测 → **组合体检**（这里出「该不该装」的结论）→ 依赖漏洞检测 → 资产关联分析 → 离线演示。
3. **讲「组合风险」时一定要用具体例子**（A 读密码 / B 格式化 / C 上报），
   光说「关联分析」老师听不懂。
4. **数字要准**：32 条规则 / 8 类威胁 / **8 个能力原子** / **7 类链路模板** /
   107 个样本 / 检出 100% / 误报 2.0% / 特异度 98% / 规则快筛 33ms /
   依赖四源查询并发 5.75× / 151 条断言
   （5.75× 是**依赖漏洞模块**的四源并发加速比，8 依赖场景 8.0s → 1.4s，不是技能检测的数）
5. **不要说**「全球首创」「业界首个」「国奖无同类实现」
6. **要说的**：可复现、CodeArts 三轮审计、1 条建议因会引入漏报被主动否决
7. **竞品表述**：说「我调研的信安国赛 45 个国奖一等奖里做 Agent 安全的 5 个全是单点检测，
   在这个调研范围内未发现做跨资产关联的实现」，说完补一句「这是我准备信安国赛时做的调研，
   Agent 安全方向整体还在早期」
