# 汇报话术 · 一页卡（过几天组会用）

> **用法**：左边是「你说什么」，右边是「被追问怎么办」。
> 背左边就行，右边是保险。
> ⚠️ **开场直接讲「AI 技能供应链安全检测」这一个问题**，
> 不要用「双链」「两条腿」这种说法 —— 老师要求功能聚焦。

## 🎤 主汇报（3.5 分钟，照念）

> 「老师好，我们汇报一下 ICT 大赛创新赛赛题一的进展。
>
> **先说这个项目是什么**：我们做的是一套 **AI 技能供应链安全检测平台**，
> 项目名 SkillGuard。它解决的是一个新出现的问题——
> AI Agent 现在靠装各种 **Skill 包**（本质是一个 `SKILL.md` 指令文件）
> 来获得能力。Snyk 去年扫了 3,984 个公开技能，
> **36.82% 至少含一个安全缺陷**。
>
> **为什么这个问题现在才出现**：Skill 天然继承 Agent 的全部权限——
> shell 访问、读环境变量里的凭据、往 IM 通道外发数据。
> 而且发布门槛极低：一个 Markdown 文件 + 一周龄的 GitHub 账号就能上架。
> 传统供应链工具（Snyk Dependabot、pip-audit、Trivy）**完全不碰 Skill**。
>
> **传统工具卡在哪**：它们只做**单点检测**——
> 一个技能一个技能单独打分，输出一个风险等级列表。
> 但攻击者会把恶意行为拆散到多个看起来各自正常的技能里。
> 于是单点检测的结论就是「每个技能最多中危」，
> **真实的系统性威胁反而漏掉了**。
>
> **我们的做法分两步**：
> 第一步用 32 条静态规则做单点检测，命中就给原文行号和规则名，当场可核验；
> 第二步是**我们的原创点**——把每个技能拆成 6 类「危险能力」建能力图，
> 再按 6 类攻击链模板在图上做路径搜索，
> **把分散的单点风险连成完整攻击链路**。
> 举个实测例子：三个技能单看分别是安全、中危、高危，
> 传统工具到此为止；我们识别出这是一条完整的**凭据外泄链路**。
> 这个模块**不新增任何检测规则**，只是把已有的单点结果重新关联，
> 所有结论都能追溯到原文行号。
>
> **另外**：传统依赖漏洞这块我们也没删，但**不做成并列功能**——
> 那条赛道 Snyk 那些工具已经很卷了。
> 我们把它降级成一个**可选的「依赖侧证据」**：
> 扫出来后在资产图谱里作为「依赖节点」，
> 和技能节点、工具节点放在一起参与组合分析。
>
> **现状**：32 条规则 / 8 类威胁、107 个真实公开样本评测
> （检出 100%、误报 2.0%、特异度 98%）、单次扫描 33 毫秒、
> 151 条回归断言全绿、语料随仓库开源、12 项第三方复现校验全绿、
> 在线 Demo 已上线。
>
> **赛题三条技术要求**：第一条用 CodeArts 码道开发，我们已经用它对
> 全部检测规则做了三轮审计，产出 11 处误报边界修正和 2 个 P0 级漏报修复，
> **这条是完成的**。第二三条是要关联 RDS、Redis 存扫描记录和缓存结果、
> 把作品部署到华为云公网、再申请大模型 API 供 AI 研判调用，
> **这三件事都需要代金券**。我们 10 月中下旬报名已经完成，
> 官方赛题页也写明代金券申请 10 月才启动，具体发放方式、额度和有效期
> 以组委会最终通知为准，现在账户还没到账，所以云上这部分还没法动手。
>
> **代码这边随时可以接上云资源**，业务逻辑一行不用改，只换数据源和部署位置。
>
> 想请老师帮忙问一下对接老师：代金券大概什么时候能发放、额度够不够开这三个资源？
> 另外赛题要求里有一条是『基于已有智能体和 Skills 关联 RDS、Redis 快速开通创建』，
> 想请教这个开通流程是走我们自己的账号，还是有指定的统一入口或者对接人？
> 我们好提前把步骤准备好。」

## 🔍 五个追问预案

| 老师问 | 你答 |
|---|---|
| 「依赖漏洞这块不是已经有 Snyk 了吗？」 | 「对，所以**我们没把它做成并列功能**——那赛道确实卷死了。我们保留它是因为两件事：一是**置信度评级**（按 NVD/GitHub/OSV 权威性加权，不是取平均），二是**EPSS 驱动的修复优先级**（CVSS 高不等于马上要修，要看 30 天内实际被利用的概率）。在作品里它是**可选的依赖侧证据**，默认不展开，不点不占版面。」 |
| 「这跟市面上的工具有什么区别？」 | 「同赛道的 SkillLens、ClawGuard、MCP-Sentinel、TraceShield **全是单点检测**——查出这个 Skill 有 13 个风险点就结束了。我们做的是**跨技能关联**：回答的不是「哪个技能危险」，而是「**这些技能凑在一起会造成什么后果**」，并给出可核验的攻击路径、真实危害和处置建议。」 |
| 「你现在具体做到哪一步了？」 | 「代码完整可跑，三个功能都通了：Skill 规则检测、组合风险分析、离线演示。传统依赖扫描作为可选附加也在。本地 32 条规则、107 个真实样本评测都过了，12 项第三方复现校验全绿，Demo 已上线。只差换数据源和部署位置。」 |
| 「代金券还没到，你们自己不能先弄吗？」 | 「赛题的部署要求是『作品在华为云上的快速部署』，评委复现时会看是不是真跑在华为云上。没有资源就开不出来，所以想问一下券的时间，我们好卡着 12 月初赛提交节点排期。」 |
| 「这个是不是套了个正则就跑？」 | 「规则部分确实有 32 条正则，但真正花功夫的是三件事：**误报治理**（100 个真实科研 Skill 里曾有 58 个误报，根因是规则分不清『文档在描述』和『技能在执行』，这是静态正则的天花板）；**关联层**（6 个能力原子建能力图 + 6 类链路模板做路径搜索 + 依赖/技能/工具统一到一张资产图谱）；**AI 工具的工程化使用**（三轮 CodeArts 审计，1 条建议被我否决，第二轮它自查出第一轮引入的 P0 缺陷导致 `os.system` 检测失效，有一次我的正则改动让误报从 6% 飙到 33%，单元测试抓不到，是真实语料抓出来的）。」 |

## ⚠️ 讲的时候注意

1. **开场讲「AI 技能供应链安全检测」这一个问题**。
   不要说「双链」「两条腿」「左手右手」——老师明确要求**功能要聚焦**。
2. **三个功能串起来讲**（这是 UI 上真实存在的）：
   Skill 安全检测 → 组合风险分析 → 离线演示。
   依赖漏洞是组合风险分析里的**折叠附加项**，讲一句带过即可，别花时间展开。
3. **数字要准**：32 条规则 / 8 类威胁 / 6 能力原子 / 6 链路模板 /
   107 个样本 / 检出 100% / 误报 2.0% / 特异度 98% / 33ms / 5.75× / 151 条断言
4. **不要说**「全球首创」「业界首个」「国奖无同类实现」
5. **要说的**：可复现、CodeArts 三轮审计、1 条建议因会引入漏报被主动否决
6. **竞品表述**：说「我调研的信安国赛 45 个国奖一等奖里做 Agent 安全的 5 个全是单点检测，
   在这个调研范围内未发现做跨技能关联的实现」，说完补一句「这是我准备信安国赛时做的调研，
   Agent 安全方向整体还在早期」
