# 汇报问答准备（给老师，5 问）

> 用法：老师问到时先给「一句话答」，再看「证据/出处」。本文件是批 7 交付物，
> 非代码、不影响任何校验。

## Q1 · 你这个跟华为云到底什么关系？

**一句话**：存储**抽象层已就绪**——`StorageBackend` 接口 + 本地实现已跑通全功能；华为云 RDS/Redis
适配为**骨架、待补齐**（`HuaweiCloudStore` 仍是 TODO）；待代金券到位后补齐适配即可上线。
AI 意图分诊用的就是**华为云 MaaS（DeepSeek）**。

**证据**：`modules/store.py`（`StorageBackend` 抽象 + `LocalStore`）、
`modules/storage/huawei.py`（RDS/Redis 骨架 + `asset_node`/`asset_edge`/`scan_record` 三张表）；
赛题 1 原文要求「关联 RDS、REDIS 等华为云服务的快速开通创建」。

> 「接口已就绪、云适配待补齐」和「没做」是两回事——这句能让老师觉得你早就规划好了。

## Q2 · 市面上 8 个商业扫描器、5 篇学术工作都做了，凭什么是你？

**一句话**：别人做**单点检测**（这个技能危不危险），我做**组合成链**（这组凑一起会怎样）。

**证据（两面互证）**：KnotScryer（arXiv:2610.32155）证明单点会**漏**——13.7% 的危险链路
全部由单点扫描器判 safe 的技能组成；本项目实测证明单点会**响**——7 个假链路场景里 5 个
也命中了「敏感凭据路径读取」。**漏（假阴性）与响（假阳性）同时存在，说明单点评分
既不能证明安全、也不能证明危险，必须回到组合层。**

## Q3 · 依赖漏洞市面一堆现成的（pip-audit / Snyk），你为什么还做？

**一句话**：① 依赖不是主线，是**关系图里的一类节点**（技能→依赖→CVE 成链）；
② 我实现的是**四源**（OSV / NVD / GitHub / EPSS），pip-audit 只查**一个源**；
③ **不重新发明 CVE 查询**——那正是我把它从独立功能**收进图谱**的原因。

## Q4 · AI 参与判定，安全吗？

**一句话**：三条硬约束——① 每条判断**带原文行号**（不用信我，自己查）；
② AI 挂了**拒判**（fail-closed，绝不输出「可安装」）；
③ **规则给确定性、AI 只给意图**，两者互不覆盖。

**证据**：`modules/adjudicator.py` 的 fail-closed 与行号校验；`docs/项目讲解手册.md` §3.6。
