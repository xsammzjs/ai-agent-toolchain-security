## ⚠️ 方法论错误已更正（重要教训）

前一版 `run_bench_eval.py` 用「Pattern 标注 → 构造典型载荷 → 跑检测」算检出率，
得出 86.6% 与三个 0%。**这是错误的方法论**：

1. **Pattern 是多标签**，如「Remote Code Execution; Behavior Manipulation」不是单一手法
2. **用标注构造载荷 = 已知答案给自己抄答案**，检出率必然虚高
3. 三个 0% 是构造逻辑的产物，**不是规则的真实盲区**

实测验证：USENIX 数据集的恶意仓库（smp_170/smp_4712/smp_9692）在 GitHub 上
**均已不存在** —— 论文做了责任披露与脱敏（confirmed malicious 的 URL withheld），
原始 SKILL.md 正文无法获取。

**教训**：做评测前必须先确认「能不能拿到原始数据」。拿不到就只能做元数据分析，
不能包装成检出率。**否则报告里是假数字，评委一问就穿。**
