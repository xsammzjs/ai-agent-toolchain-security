## 协作方式约定（有效，请沿用）
- 用户要求**诚实直接，不哄不灌鸡汤**。推测性结论必须标注可信度。
- 用户焦虑时会反复推演概率而不行动；此时应指出"哪个动作成本最低、能闭环"，
  而不是继续帮他算概率。但**一旦用户明确说不做，就停止推进**，不要反复劝。
- 涉及改代码时，先建回滚手段（git）+ 回归测试锁住现有行为，再动手。
- 给出结论时附**实测数据**，不要只下判断。
- **工具失败要如实说明并给证据链**：例如AudioTranscribe 连 10 秒切片都超时，
  应说明是服务端故障而非能力问题，并给出替代方案（本项目已装 faster-whisper 备用）。

## 战略转向（诊断报告核心结论）
从「依赖漏洞扫描工具」→「**AI Agent 供应链安全检测与决策平台**」。
理由：传统依赖扫描同类产品太多（Snyk/Dependabot/pip-audit/Trivy/OSV-Scanner），创新性难服众；
而 `skill_scanner.py`（23 条 Agent Skill 安全规则，参考 OWASP Agentic Skills Top10 + Snyk ToxicSkills）
是唯一真正有"AI 时代新意"的资产。依赖扫描降级为证据来源之一——
这也正好呼应项目名"双链"（传统软件供应链 + AI 供应链）。
